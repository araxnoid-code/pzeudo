##### 0.0.2-dev.1-no_grad
_1 Aug 2026_
- added new methods to StorageGrad
  - StorageGrad::remove_grad
  - StorageGrad::no_grad

- To enable the no_grad feature (mainly making a tensor have no_grad status or not have a gradient which is automatically not involved in backwards), StorageGrad is given an additional handler to perform validation using: 
  - time, each push, remove and no_grad operation will add time to a certain index (every index has a time). Useful for preventing a tensor from accessing a gradient that doesn't belong to it because mid-way through a tensor is set no_grad which will delete the gradient at its index, but after that the index is reused for the gradient of the new tensor. 
  - status, each index will have a status, status is divided into 3, namely: 
    - 0: Remove 
    - 1: no grad 
    - 2: value 
  By dividing this state, the tensor that accesses the gradient index that is deleted because no_grad will have a different error and will be handled further, differently from the gradient that is deleted because of remove.

- Due to updated changes that have occurred above. then the StorageType enum in the StorageType::Arr field has an additional value, namely `StorageType::Arr(usize, Option<usize>)` 
  - Likewise what happens to ViewStorageType::storage which becomes `ViewStorageType::Storage(usize, Option<usize>)`

_2 Aug 2026_
- Added a generic trait to the Tensor `Tensor<F, T, G>`, which serves as a marker for whether the tensor has a Grad or not and also handles the creation of a tensor without a gradient.
  - Type G must implement GradStatTrait. Types that implement it include:
    - `Grad`, use if you want a tensor with a grad
    - `NoGrad`, use if you want a tensor without a grad
  - The main change to initializing a tensor using a Module (except permanent ones) is that it is now required to initialize it to the Grad or NoGrad type.

_2 Aug 2026_
- Added the GradStatTrait::zeros_grad method to determine whether or not to create a gradient. Grad and NoGrad implement this trait and method.

- Added the `Tensor<F, Contiguous, Grad>::no_grad` method to disable gradients on tensors that have gradients.
- Currently, this only works for gradients in GradStorage. If the gradient is permanent or in metadata (view), it will return Err.

- Added the `Tensor<F, Contiguous, NoGrad>::with_grad` method to add a gradient to a tensor that initially has no_grad status.

_2 Aug 2026_
- The tools folder in pzeudo_tensor is now a single file called tools.rs

- Added GradStorage methods:
  - GradStorage::check_time_not_match
  - GradStorage::no_grad

- Added the tools function check_no_grad_or_time_not_match (in tools.rs)

- add a new parameter to Tensor::add, namely grad, which will accept a data type that implements GradStatTrait

- Modified the add_backward function to use check_no_grad_or_time_not_match to handle no_grad.
  - is of a testing nature, if successful it will be used in other backward functions

- The mechanism for deleting values in GradStorage (remove) that are unrelated to no_grad has been made a private method, as there is no handler for removing grad.
