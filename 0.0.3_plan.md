_23 Aug 2026_
- Added the Dropout struct.
  - p here represents the probability of zeroing out or dropping a value. 
  - Uses inverted dropout. 
  - Uses smallRng for the Bernoulli distribution.
  - Includes Dropout::forward. 
  - However, it cannot yet be used for the backward pass.

_23 Aug 2026_
- add dropout_backward

_23 Aug 2026_
- added the PhaseStatus trait which functions to determine the training or eval phase.
  - The phase is divided into two structs.
    - TrainPhase
      - also implements ReqGradTrait.
      - The function is proportional to Grad.
    - EvalPhase
      - also implements ReqGradTrait.
      - The function is proportional to NoGrad.
  - This phase can function as either Grad or NoGrad, making it useful for certain methods. It also adds clarity to the model phase.

- Dropout::forward will not accept requires_grad but will accept phase (TrainPhase/EvalPhase).
  - TrainPhase
    - Executes a formula based on the Bernoulli distribution and produces a new tensor.
  - EvelPhase
    - It immediately returns a new tensor containing the same array data, state, and record as the previous tensor. The only difference is that the gradient is `None` (the previous tensor remains unaffected).

##### 0.0.3-dev.1-no_update
_12 Aug 2026_
- Added an update property to ParamsStorage and GradStorage.
- The update property serves as a flag indicating whether the corresponding gradient has been updated.

- Added an is_update method to ParamsStorage and GradStorage.

- Renamed the function check_no_grad_or_time_not_match to is_no_grad_or_time_not_match_or_no_update. 
  - The addition of '_or_no_update' to the function name reflects the change in functionality: it now also checks whether the gradient has been updated. 
  - The names of the functions GradStorage::check_no_grad and GradStorage::check_time_not_match were also updated by replacing 'check' with 'is'.

_12 Aug 2026_
- Added methods:
  - GradStorage
    - GradStorage::set_update
  - ParamsStorage
    - ParamsStorage::set_update
  - ArrayStorage
    - ArrayStorage::set_grad_update

- Updated arithmetic operation backward passes: the update status of the relevant gradient is now set to 'true' after the backward function executes.

- Changed the record structure to `Vec<Option<RecordLabel<F>>>`.

- Added the RecordStatus enum.

- Added the record_status property with the data type `Option<RecordStatus>`:
  - record_status is used to mark specific indices in the record where the connection should be severed during the backward phase. 
  - record_status and the update status work in tandem, when a record connection is severed, the update status of the associated gradient remains unchanged. Gradients with an update status of 'false' are skipped, eliminating the need for gradient calculations if the parent gradient's connection has already been severed.

- Currently undergoing adjustments due to fundamental structural changes.

_12 Aug 2026_
- The activation function has been adjusted to include record_status.

- The view method has been adjusted to include record_status.

- The unary method has been adjusted to include record_status.

- Matmul 2D and Matmul ND have been adjusted to include record_status.

- arithmetic have been adjusted to include record_status.

_13 Aug 2026_
- All backward functions can now handle the no_update status.

- ParamsStorage::push now pushes a value of false for the update property by default.

- Added OptimizerTrait to pzeudo_module/optim
  - All zero_grad methods across all optimizers have been moved to OptimizerTrait::zero_grad. 
  - Using OptimizerTrait::zero_grad now directly sets the update status in the parameter storage to false.

_13 Aug 2026_
- Created ModuleBuilder.
  - the creation of parameters and ModelBuilder instances now proceeds through ModuleBuilder to ensure that no new creation parameters or models within the same module cause conflicts.
  - The module itself can be obtained using the ModuleBuilder::build() method, which accepts a type as the model.

_13 Aug 2026_
- A record_status property has been added to the tensor (this change was made in a previous commit).

- Fixed is_no_grad_or_time_not_match_or_no_update, which was incorrectly checking the 'no update' status.

- The Record entity, originally a vector of RecordLabels, is now a Record struct with two properties:
  - record: stores the record label. 
  - skip: stores a flag indicating whether the record label at the corresponding index should be executed.

- Added the following methods:
  - Tensor::unrecord
    - Changes the tensor status from Record to UnRecord.
    - Sets the skip value (within the Record struct) at the index corresponding to the tensor's stored record index to true. 
  - Tensor::record
    - Changes the tensor status from UnRecord to Record.
    - Sets the skip value (within the Record struct) at the index corresponding to the tensor's stored record index to false.

- added code testing for the unrecord mechanism.
